# 8 · Running the AI backend on your PC

The app never holds an AI key. It sends requests to the **EduMate backend** (the `backend/` folder), which runs on your PC, adds the Claude API key, calls Claude and sends the result back. While the backend runs, the debug app produces real lesson plans and worksheets instead of offline templates.

```
Emulator / phone ──HTTP──▶ backend on your PC (127.0.0.1:8080) ──HTTPS──▶ Claude API
```

Use demo topics and made-up data only until the compliance items in `docs/07-roadmap.md` are done.

---

## Part A · Get a Claude API key (one time)

1. Go to **https://console.anthropic.com** and sign in or create an account.
2. Open **Settings → Billing** and add credit. Generation is pay-per-use.
3. *(Recommended)* Open **Settings → Limits** and set a monthly spend limit you're comfortable with.
4. Open **API Keys → Create Key**. Name it `edumate-local`, click **Create**, then **copy the key**. It starts with `sk-ant-` and is shown only once.

Treat the key like a password: never paste it into chat, email or the app, and never commit it to GitHub.

**Rough cost:** the backend uses Claude Opus 5.5 ($4 input / $20 output per million tokens). A lesson plan is usually a few US cents to about $0.20; a worksheet with three versions and answer keys is usually $0.10 to $0.50. Check **Usage** in the Console after a few runs to see your actual cost.

## Part B · Get the new code (Android Studio)

1. **☰ → Git → Pull…** (or **Git → Update Project**, Ctrl+T) and click **OK**. If asked about local changes, keep the default (*Stash* or *Shelve*).
2. If a bar appears at the top saying Gradle files changed, click **Sync Now**.

## Part C · Add your key to the backend

1. In the **Project** panel on the left, click the dropdown at the top that says **Android** and change it to **Project**. You'll now see a `backend` folder.
2. Open `backend`. Right-click **secrets.properties.example → Copy**, then right-click the **backend** folder → **Paste**. Name the copy exactly `secrets.properties` and click **OK**.
3. Open `secrets.properties` and replace `sk-ant-REPLACE_ME` with your key:
   ```
   ANTHROPIC_API_KEY=sk-ant-api03-...your key...
   ```
4. Press **Ctrl+S**. The file name should look greyed out or olive, which means Git ignores it and it can't be committed.

## Part D · Start the backend

1. Open the **Terminal** (Alt+F12) and run:
   ```bash
   .\gradlew :backend:run
   ```
2. The first start downloads libraries and takes 1–3 minutes. It's ready when you see:
   ```
   EduMate SG backend is running
     Model:            claude-opus-5-5
   ```
   Gradle shows a progress line like `<==========---> 80% EXECUTING`. That's normal: the backend keeps running until you stop it.
3. **Check it works:** open **http://127.0.0.1:8080/health** in a browser on your PC. You should see `{"status":"ok","model":"claude-opus-5-5"}`.
4. **Leave this Terminal tab running.** For other commands, open a second tab with the **+** at the top of the Terminal panel.

To stop the backend, click in its Terminal tab and press **Ctrl+C**.

## Part E · Use real AI in the app (emulator)

1. Start the emulator, then in the **second** Terminal tab run:
   ```bash
   .\gradlew :app:installDebug
   ```
   You can also click the green ▶.
2. In the app, open **Today → shield icon (Privacy & data)** and make sure **AI features** is **on**. If it's off, the app uses offline templates and sends nothing to the AI.
3. Go to **Plan**, pick a topic and streams, and tap **Generate lesson plan**. It usually takes **30 seconds to 2 minutes**.
4. Check the result is real AI output:
   - The card at the top says **AI draft · not yet reviewed** with **no** "Offline template" line.
   - Tap the card. It shows **Generated by edumate-backend-v1**, plus the syllabus outcomes and sources.
   - The backend Terminal tab prints a line such as `generated 9421 chars in 48213 ms`.
5. Try **Plan → Worksheets → New worksheet** too. Worksheets use deeper reasoning, so they take longer, but their answer keys are worked out properly.

## Part F · Use real AI on your phone (USB cable)

The backend only accepts connections from your own PC. A phone reaches it through the USB cable using `adb reverse`.

1. Turn on **USB debugging** (on Samsung, first turn off **Auto Blocker**) and connect the phone.
2. Open **`local.properties`** in the project's top folder (Android Studio created it) and add this line at the end:
   ```
   edumate.apiBaseUrl=http://127.0.0.1:8080/
   ```
3. With the backend running, run this in the second Terminal tab:
   ```bash
   & "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" reverse tcp:8080 tcp:8080
   ```
   Repeat this every time you reconnect the phone or restart the emulator.
4. Select your phone in the device box at the top and press ▶.

This works only while the phone is connected by USB and the backend is running. To use the app anywhere without a cable, the backend needs to be hosted online (Google Cloud Run in Singapore is the planned next step). The `adb reverse` command also works for the emulator, so you can keep this setting for both.

## Troubleshooting

| What you see | Cause | Fix |
|---|---|---|
| The result card says **Offline template** | The app couldn't reach the backend, or AI features are off | Check the backend tab is still running and http://127.0.0.1:8080/health works; check **AI features** is on; on a phone, re-run the `adb reverse` command |
| `*** EduMate backend could not start *** No Claude API key found` | `secrets.properties` missing, misnamed, or still has `REPLACE_ME` | Redo Part C; the file must be inside `backend/` and named exactly `secrets.properties` |
| "The backend's Claude API key was rejected" | Wrong or deleted key | Create a new key (Part A) and paste it again |
| "The AI service returned an error (400)…" and the backend tab mentions **credit balance** | No credit left | Add credit in Console → Billing |
| "The AI service is busy" / "overloaded" | Rate limit or temporary overload | Wait a minute and try again |
| "Your notes contain an NRIC/FIN, email address or phone number" | Privacy protection working as intended | Remove personal details from the notes |
| "The AI declined this request" | A safety filter was triggered | Rephrase your notes; ordinary teaching topics should not trigger it |
| `Address already in use` when starting | A backend is already running | Use the existing one, or close the old Terminal tab |
| "The backend could not reach the AI service" | The PC has no internet, or the network blocks `api.anthropic.com` (common on school networks) | Try another network, e.g. home Wi-Fi or a phone hotspot |
| Generation takes more than 3 minutes, then shows a template | The app stopped waiting | Use fewer questions or streams; the next attempt is usually faster |

## Settings you can change (in `backend/secrets.properties`)

| Setting | Default | Purpose |
|---|---|---|
| `EDUMATE_MODEL` | `claude-opus-5-5` | The Claude model used for generation |
| `EDUMATE_PORT` | `8080` | Change it if 8080 is taken (then update `edumate.apiBaseUrl` to match) |
| `EDUMATE_DEV_TOKEN` | *(none)* | If set, the app must send the same token: add `edumate.devToken=…` to `local.properties` |

## What the backend does

- Uses Claude **structured outputs**, with a JSON schema generated from the app's own data classes, so responses always fit the app.
- Uses **adaptive thinking**: moderate effort for lesson plans, high effort for worksheets (so answer keys are correct), low effort for feedback.
- **Re-checks for NRIC/FIN, emails and phone numbers** (the app already removes these before sending) and rejects any request that still contains them.
- **Moderates** all AI output before returning it.
- **Keeps only citations of resources the teacher selected**, with their titles and licences rebuilt from the original records.
- Turns on Claude's **refusal fallback**: if a safety filter wrongly declines an ordinary teaching request, it is retried automatically on another suitable model.
- Logs only request paths, timings and status codes. It never logs prompts, generated content or the API key.
